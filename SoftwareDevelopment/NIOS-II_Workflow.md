# Nios II Complete Workflow

## What You Get

Note: THis workflow works the same for Windows and Ubuntu, you just start with the two Linux files first!
Two files to start with — place both in the **same folder**
(e.g. `SoftwareDevelopment/NIOS-II/`):

```
open_shell.bat        ← double-click from Windows to open the shell
NIOS-II_setup.sh      ← run ONCE inside the shell to configure everything
```

After setup, these are generated automatically in the same folder:

```
new_project.sh        ← generate BSP + Makefile (run once)
update_makefile.sh    ← rescan .c/.h files, regenerate Makefile
build.sh              ← compile the application
download.sh           ← load .elf onto FPGA via JTAG
terminal.sh           ← open Nios II terminal (printf output)
rebuild_bsp.sh        ← regenerate BSP after hardware changes
run_sim.sh            ← convert ELF to HEX and prep ModelSim simulation
```

## First Time Setup

### Step 1 — Open the shell

Double-click `open_shell.bat` from Windows File Explorer.

This opens the **Nios II Command Shell** (bash) already `cd`'d
to the folder where the `.bat` file lives.

### Step 2 — Fix permissions and run setup

Inside the shell:

```bash
chmod +x NIOS-II_setup.sh
dos2unix NIOS-II_setup.sh      # fixes Windows line endings
./NIOS-II_setup.sh
```

It will ask four questions:

```
SOPCINFO path:
  → /mnt/d/Escritorio/FPGA-MusicPlayer-HPS-NIOS/MusicPlayerQuartus/MusicPlayerPlatformDesign.sopcinfo

Software root path:
  → /mnt/d/Escritorio/FPGA-MusicPlayer-HPS-NIOS/SoftwareDevelopment/NIOS-II

CPU name [CPU_NIOS_II]:
  → (press Enter to accept default)

GCC path:
  → (auto-detected, press Enter to accept)
```

**Always use bash-style paths** (`/mnt/d/...`), never Windows paths (`D:\...`).

Then it shows a **confirmation summary** — review it and press Enter to proceed
or type `n` to abort and re-run.

After confirming, setup will:
- Create `app/src/`, `app/lib/`, `app/include/` (if they don't exist)
- Write a starter `main.c` **only if no `.c` files are found anywhere in `app/`**
- Generate all `.sh` scripts with `chmod +x` already applied

### Step 3 — Generate BSP and Makefile

```bash
./new_project.sh
```

This runs three things internally:
1. `nios2-bsp hal` → generates `bsp/` with `system.h`, drivers, linker script
2. `nios2-app-generate-makefile.exe` → generates `app/Makefile`
3. `make -C bsp` → compiles the BSP library

## Every Time You Change Code

```bash
# 1. Edit your .c files (in app/, app/src/, app/lib/)

# 2. Compile
./build.sh
#    Output ELF: app/main.elf

# 3. Make sure FPGA is programmed (Quartus Programmer → .sof)

# 4. Load the ELF onto the FPGA
./download.sh

# 5. See printf/alt_putstr output
./terminal.sh
```

---

## When You Add New Source Files

```bash
# 1. Add your_file.c  →  app/src/
# 2. Add your_file.h  →  app/include/

# 3. Re-generate the Makefile to include new files
./update_makefile.sh

# 4. Rebuild
./build.sh
```

---

## When Hardware Changes (Platform Designer edit)

```bash
# 1. Platform Designer → Generate HDL
# 2. Quartus → Processing → Start Compilation
# 3. Quartus → Tools → Programmer → reprogram .sof

# 4. Regenerate BSP (deletes old bsp/ and rebuilds from scratch)
./rebuild_bsp.sh

# 5. Recompile app against new BSP
./build.sh

# 6. Download to FPGA
./download.sh
```

Your source code in `app/src/`, `app/lib/`, `app/*.c` is never touched
by `rebuild_bsp.sh`.

## Running a ModelSim Simulation

### Step 1 — Build the ELF

```bash
./build.sh
```

### Step 2 — Prepare simulation files

```bash
./run_sim.sh
```

This does three things:
1. Copies `app/main.elf` to the testbench mentor folder
2. Reads `RAM_BASE` from `bsp/system.h`
3. Converts ELF → RAM HEX using `elf2hex.exe` and writes it to the
   simulation submodules folder

At the end it prints the exact ModelSim commands to run.

### Step 3 — Run ModelSim

Open ModelSim, then in the Transcript panel:

```tcl
cd {D:\...\MusicPlayerPlatformDesign\testbench\mentor}
do msim_setup.tcl
add wave /MusicPlayerPlatformDesign_tb/*
ld_debug
run 2.5ms
```

To re-run after a code change:

```tcl
restart -f
ld_debug
run 2.5ms
```

Only redo `do msim_setup.tcl` if you closed and reopened ModelSim.

## Using Eclipse IDE (optional)

Instead of `./download.sh`, you can use Eclipse for debugging with breakpoints:

```
Quartus → Tools → Nios II Software Build Tools for Eclipse
File → Import → General → Existing Projects into Workspace
→ Browse to your SW_ROOT folder
→ Select both the app and bsp projects → Finish

Right-click app → Build Project             (equivalent to ./build.sh)
Right-click app → Run As → Nios II Hardware (equivalent to ./download.sh)
```

Terminal output still works with `./terminal.sh` or:

```
Quartus → Tools → Nios II Command Shell [gcc4] → nios2-terminal.exe
```

## Common Errors

**`nios2-bsp: Can't find SOPC design file`**
→ The `.sopcinfo` path is wrong or doesn't exist.
→ Always use bash paths: `/mnt/d/...` not `D:\...`

**`./new_project.sh: Permission denied`**
→ Run `chmod +x *.sh` first.

**`bad interpreter: No such file or directory`**
→ Windows line endings in the `.sh` file.
→ Run `dos2unix *.sh` then retry.

**`nios2-elf-gcc.exe: No such file or directory`** (during BSP build)
→ GCC path is wrong. Re-run `NIOS-II_setup.sh` and correct the GCC path.

**`nios2-download: No JTAG device`**
→ FPGA not programmed yet.
→ Run Quartus Programmer first, then `./download.sh`.

**`elf2hex.exe: command not found`**
→ The nios2eds bin is not on PATH.
→ Re-run `NIOS-II_setup.sh` — the GCC path export fixes this.

**`nios2-terminal.exe: command not found`**
→ Same PATH issue. Re-run setup.
