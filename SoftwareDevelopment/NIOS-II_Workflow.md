# Nios II Complete Workflow (Linux Native)

> **Linux only.** This workflow uses the native Linux Nios II EDS tools
> (`nios2-bsp`, `nios2-app-generate-makefile`, `elf2hex`, `quartus_cdb`, ...).
> No WSL, no `.exe`, no `.bat`. It is **not** compatible with Windows.

## What You Get

One file to start with — place it in the software root scripts folder
(e.g. `SoftwareDevelopment/NIOS-II/`):

```
01Setup.sh        ← run ONCE to configure everything
```

After setup, these are generated automatically in the same folder:

```
02NewProject.sh   ← generate BSP + Makefile, build BSP (run once)
03UpdateMake.sh   ← rescan .c files, regenerate the app Makefile
04Build.sh        ← compile the application (forces -Os, cleans obj/)
05Download.sh     ← load main.elf onto the FPGA via JTAG
06Terminal.sh     ← open nios2-terminal (printf/alt_putstr output)
07RebuildBsp.sh   ← delete and regenerate the BSP after hardware changes
08RunSim.sh       ← convert ELF to HEX and prep the ModelSim simulation
09MakeSof.sh      ← embed the ELF into on-chip RAM and re-assemble the .sof
```

## First Time Setup

### Step 1 — Run setup

```bash
chmod +x 01Setup.sh
./01Setup.sh
```

Setup first **auto-detects** the Quartus/Nios II installation (it searches
`~/intelFPGA_lite`, `~/intelFPGA`, `/opt/intelFPGA*`, etc. for versions
22.1std down to 20.1). If nothing is found it aborts — install Quartus with
the Nios II EDS first.

Then it asks:

```
SOPCINFO path:
  → /home/adriel/FPGA-MusicPlayer-HPS-NIOS/MusicPlayerQuartus/MusicPlayerPlatformDesign.sopcinfo

Software root:
  → /home/adriel/FPGA-MusicPlayer-HPS-NIOS/SoftwareDevelopment/NIOS-II

CPU name [CPU_NIOS_II]:
  → (Enter to accept default)

GCC path:
  → (auto-detected, Enter to accept)

Stack pointer [none]:
  → e.g. 0xE000 to add -Wl,--defsym,__alt_stack_pointer=...
    or Enter to omit the linker flag entirely

Quartus project name:
  → auto-detected from the .qpf next to the .sopcinfo, Enter to accept

RAM name [RAM_NIOS_II]:
  → on-chip RAM component name in Platform Designer (used by 09MakeSof.sh)
```

Then it shows a **confirmation summary** — press Enter to proceed or type
`n` to abort and re-run.

After confirming, setup will:
- Create `app/src/`, `app/lib/`, `app/include/` (if they don't exist)
- Write a starter `main.c` **only if no `.c` files are found anywhere in `app/`**
- Generate `02`–`09` scripts with all paths baked in and `chmod +x` applied

### Step 2 — Generate BSP and Makefile

```bash
./02NewProject.sh
```

This runs three things internally:
1. `nios2-bsp hal` → generates `bsp/` with `system.h`, drivers, linker script
   (configured lean: reduced device drivers, small C library, lightweight
   driver API, no system clock / timestamp timer, `exit` disabled)
2. `nios2-app-generate-makefile` → generates `app/Makefile` from every `.c`
   found under `app/`, with `app/include/` on the include path
3. `make -C bsp` → compiles the BSP library

## Every Time You Change Code

```bash
# 1. Edit your .c files (in app/, app/src/, app/lib/)

# 2. Compile (forces -Os, removes obj/ and main.objdump after build)
./04Build.sh
#    Output ELF: app/main.elf

# 3. Make sure the FPGA is programmed (Quartus Programmer → .sof)

# 4. Load the ELF onto the FPGA
./05Download.sh

# 5. See printf/alt_putstr output (CTRL+C to exit)
./06Terminal.sh
```

---

## When You Add New Source Files

```bash
# 1. Add your_file.c  →  app/src/
# 2. Add your_file.h  →  app/include/

# 3. Re-scan sources and regenerate the Makefile
./03UpdateMake.sh

# 4. Rebuild
./04Build.sh
```

---

## When Hardware Changes (Platform Designer edit)

```bash
# 1. Platform Designer → Generate HDL
# 2. Quartus → Processing → Start Compilation
# 3. Quartus → Tools → Programmer → reprogram .sof

# 4. Regenerate BSP (deletes old bsp/ and rebuilds from scratch)
./07RebuildBsp.sh

# 5. Recompile app against the new BSP
./04Build.sh

# 6. Download to FPGA
./05Download.sh
```

Your source code in `app/src/`, `app/lib/`, `app/*.c` is never touched by
`07RebuildBsp.sh`.

## Embedding the Firmware in the Bitstream (09MakeSof.sh)

Instead of downloading the ELF over JTAG every power-up, the firmware can be
**embedded into the on-chip RAM initialization** of the bitstream itself.
After this, programming the `.sof` is enough — the Nios II boots automatically
with no `nios2-download` step.

```bash
./04Build.sh      # produce a fresh main.elf
./09MakeSof.sh
```

What it does:
1. `make -f mem_init.mk mem_init_generate` in the BSP → builds the RAM init
   HEX (`<SoC>_<RAM>.hex`) from the ELF
2. Copies the HEX into the Quartus project root
3. `quartus_cdb <project> --update_mif` → updates RAM contents in the fitted
   database (no full recompilation)
4. `quartus_asm <project>` → re-assembles `output_files/<project>.sof`

Load the resulting `.sof` with Quartus Programmer — the firmware runs from
power-on.

## Running a ModelSim Simulation

### Step 1 — Build the ELF

```bash
./04Build.sh
```

### Step 2 — Prepare simulation files

```bash
./08RunSim.sh
```

This does three things:
1. Copies `app/main.elf` to `<SoC>/testbench/mentor/`
2. Reads the on-chip `RAM_*_BASE` address from `bsp/system.h`
3. Converts ELF → `<SoC>_RAM.hex` with `elf2hex` and writes it into the
   testbench `simulation/submodules/` folder

At the end it prints the exact ModelSim commands to run.

### Step 3 — Run ModelSim

Open ModelSim, then in the Transcript panel:

```tcl
cd <path>/MusicPlayerPlatformDesign/testbench/mentor
do msim_setup.tcl
add wave /MusicPlayerPlatformDesign_tb/*
ld_debug
run 2.5ms
```

To re-run after a code change (after `./04Build.sh` + `./08RunSim.sh`):

```tcl
restart -f
ld_debug
run 2.5ms
```

Only redo `do msim_setup.tcl` if you closed and reopened ModelSim.

## Common Errors

**`ERROR: Could not auto-detect Nios II installation`** (during 01Setup.sh)
→ Quartus/Nios II EDS not found in the standard locations.
→ Install Intel Quartus (20.1–22.1std) with Nios II EDS, or check the
  expected paths (`~/intelFPGA_lite/<ver>/nios2eds/...`).

**`nios2-bsp: Can't find SOPC design file`**
→ The `.sopcinfo` path given to setup is wrong or doesn't exist.

**`./02NewProject.sh: Permission denied`**
→ Run `chmod +x 0*.sh` (setup applies this automatically; only needed if
  the files were copied without permissions).

**`nios2-app-generate-makefile not found in PATH`**
→ GCC/EDS path is wrong. Re-run `01Setup.sh` and correct the GCC path.

**`nios2-download: No JTAG device`**
→ FPGA not programmed yet.
→ Run Quartus Programmer first, then `./05Download.sh`.

**`elf2hex: command not found`**
→ The nios2eds bin is not on PATH. Re-run `01Setup.sh`.

**`ERROR: RAM base not found in system.h`** (during 08RunSim.sh)
→ The BSP hasn't been generated, or the on-chip RAM component doesn't
  contain `RAM_` in its name. Run `./02NewProject.sh` first.
