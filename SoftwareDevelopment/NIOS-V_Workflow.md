# Nios V Complete Workflow

## What You Get

Two files to start with — place both in the **same folder**
(e.g. `SoftwareDevelopment/NIOS-V/`):

```
NIOS-V_Shell.bat      ← double-click from Windows to open the Nios V shell
NIOS-V_setup.bat      ← run ONCE inside the shell to configure everything
```

After setup, these are generated automatically in the same folder:

```
new_project.bat       ← generate BSP + CMake project (run once)
rebuild_bsp.bat       ← regenerate BSP after hardware changes
update_cmake.bat      ← rescan .c/.h files, regenerate CMakeLists.txt
terminal.bat          ← open JTAG terminal (juart-terminal, printf output)
run_sim.bat           ← convert ELF to HEX and prep ModelSim simulation
```

> **Note:** There is no `build.bat` or `download.bat` — building and loading
> to the FPGA are handled entirely by **AshlingRiscFree IDE**.

```
            ├── include/                       ← your .h header files
            └── build/
                └── Default/

```

## First Time Setup

### Step 1 — Open the Nios V shell

Double-click `NIOS-V_Shell.bat` from Windows File Explorer.

This opens the **Nios V Command Shell** already `cd`'d to the folder
where the `.bat` file lives.

### Step 2 — Run setup

Inside the shell:

```cmd
NIOS-V_setup.bat
```

It will ask four questions:

```
SOPCINFO path:
  → D:\Escritorio\FPGA-MusicPlayer-HPS-NIOS\MusicPlayerQuartus\MusicPlayerPlatformDesign.sopcinfo

Software root path:
  → D:\Escritorio\FPGA-MusicPlayer-HPS-NIOS\SoftwareDevelopment\NIOS-V

CPU name [CPU_NIOS_V]:
  → (press Enter to accept default)

Tools path:
  → (auto-detected, press Enter to accept)
```

**Always use Windows-style paths** (`D:\...`), not bash paths (`/mnt/d/...`).

Then it shows a **confirmation summary** — review it and press Enter to proceed
or type `n` to abort and re-run.

After confirming, setup will:
- Create `app\src\`, `app\lib\`, `app\include\`, `app\build\`, `bsp\`
- Write a starter `main.c` **only if no `.c` files are found anywhere in `app\`**
- Generate all `.bat` scripts

### Step 3 — Generate BSP and CMake project

```cmd
new_project.bat
```

This runs internally:
1. `niosv-bsp` → generates `bsp\` with `system.h`, drivers, linker script
2. `niosv-app` → generates `app\CMakeLists.txt` for RiscFree IDE

### Step 4 — Import into AshlingRiscFree IDE

```
File → Import Nios V CMake project...
→ Navigate to your app\ folder
→ Select Folder → Finish
```

The project appears in Project Explorer. To also see BSP headers in the tree (optional):
```
Right-click project → New → Folder → Advanced >>
→ Link to alternate location → browse to bsp\
→ Name it "bsp" → Finish
```

## Every Time You Change Code

```
1. Edit your .c files in RiscFree IDE (app\, app\src\, app\lib\)

2. Build inside RiscFree IDE
   CTRL+B  (or click the hammer icon)
   Output ELF: app\build\Default\app.elf

3. Make sure FPGA is programmed (Quartus Programmer → .sof)

4. Load and debug via RiscFree IDE:
   Run → Debug Configurations...
   → Ashling RISC-V Hardware Debugging
   → C/C++ Application: app\build\Default\app.elf
   → Debugger tab → Auto-detect Scan Chain → Run

5. See printf/alt_putstr output:
   terminal.bat
```

---

## When You Add New Source Files

```
1. Add your_file.c  →  app\src\
2. Add your_file.h  →  app\include\

3. Re-generate CMakeLists.txt to include new files:
   update_cmake.bat

4. In RiscFree IDE: Project → Clean → CTRL+B
```

---

## When Hardware Changes (Platform Designer Edit)

```
1. Platform Designer → Generate HDL
2. Quartus → Processing → Start Compilation
3. Quartus → Tools → Programmer → reprogram .sof

4. Regenerate BSP (deletes old bsp\ and rebuilds):
   rebuild_bsp.bat

5. In RiscFree IDE: Project → Clean → CTRL+B
```

Your source code in `app\src\`, `app\lib\`, `app\*.c` is never touched
by `rebuild_bsp.bat`.

## Running a ModelSim Simulation

### Step 1 — Build the ELF in RiscFree IDE

```
CTRL+B
```

Output: `app\build\Default\app.elf`

### Step 2 — Prepare simulation files

```cmd
run_sim.bat
```

This does three things:
1. Copies `app\build\Default\app.elf` to the testbench mentor folder
2. Reads `RAM_BASE` and `RAM_SPAN` from `bsp\system.h`
3. Converts ELF → RAM HEX using `elf2hex` and writes it to the
   simulation submodules folder

At the end it prints the exact ModelSim commands to run.

### Step 3 — Run ModelSim

Open ModelSim, then in the Transcript panel:

```tcl
cd {D:\...\MusicPlayerPlatformDesign\testbench\mentor}
do msim_setup.tcl
add wave /MusicPlayerPlatformDesign_tb/*
ld_debug
run 2.5ms
```

To re-run after a code change:

```tcl
restart -f
ld_debug
run 2.5ms
```

Only redo `do msim_setup.tcl` if you closed and reopened ModelSim.

|---|---|
| `NIOS-V_Shell.bat` | Any time you need the Nios V shell |
| `NIOS-V_setup.bat` | Once per project |

## Common Errors

**`niosv-bsp: Can't find SOPC design file`**
→ The `.sopcinfo` path is wrong. Use Windows paths: `D:\...` not `/mnt/d/...`

**`niosv-bsp: command not found`**
→ Tools path is wrong. Re-run `NIOS-V_setup.bat` and correct the tools path.

**`juart-terminal: No JTAG device`**
→ FPGA not programmed yet. Run Quartus Programmer first.

**`elf2hex: command not found`**
→ Tools path is wrong. Re-run `NIOS-V_setup.bat`.

**ELF not found when running `run_sim.bat`**
→ Build the project in RiscFree IDE first (CTRL+B), then re-run `run_sim.bat`.

**CMake only runs phase 1 in RiscFree (no compilation)**
→ `Project → Clean` then `CTRL+B` again. Normal on first import.
